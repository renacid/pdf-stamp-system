# PDF捺印室

ブラウザだけでPDFを読み込み、赤い丸印を追加して保存する静的Webアプリです。サーバー側の処理、API、アカウント、PDFデータの外部送信はありません。GitHubへのアップロード・公開はまだ行っていません。

## ローカルで試す

Node.js 22.13以上（推奨：24 LTS）を使用します。

```powershell
npm.cmd install
npm.cmd run dev
```

表示されたローカルURLをブラウザで開きます。「サンプルPDFで試す」で2ページの書類を生成できます。PDFを選択すると、指定ページの捺印済みプレビューが表示され、「捺印済みPDFを保存」で全ページを含むPDFをダウンロードできます。

Node.jsはローカル開発・ビルド用です。公開後はHTML/CSS/JavaScriptと静的アセットのみを使用し、Node.jsサーバーは不要です。ES modulesとPDF.jsのWorkerを使用するため、HTMLのダブルクリック（file://）ではなくHTTP/HTTPSで開いてください。

## 設定URL

```text
https://YOUR-NAME.github.io/YOUR-REPOSITORY/?text=高橋&page=1&x=20&y=20&size=20&unit=mm&opacity=1&rotation=0
```

|パラメーター|内容|初期値|
|---|---|---|
|`text`|捺印文字。1〜12文字の縦書き|高橋|
|`page`|1始まりのページ番号|1|
|`x`|表示ページ左端から、回転前のハンコ左端まで|20|
|`y`|表示ページ上端から、回転前のハンコ上端まで|20|
|`size`|ハンコの直径。0より大きく1000以下|20|
|`unit`|座標とサイズの単位。`mm` または `pt`|mm|
|`opacity`|0＝完全透明、1＝不透明|1|
|`rotation`|中心を軸に時計回り。−360〜360度|0|

1インチ＝25.4mm＝72pt。PDF自体が回転・切り抜きされていても、画面上のページ左上を基準にします。ハンコの回転中心は指定位置に置いた円の中心です。

フォーム変更時にアドレスバーと設定URLを更新します。「URLをコピー」またはブックマークで書類ごとの設定を保存できます。単位を切り替えても入力された数値はそのまま維持され、新しい単位で解釈します。再度開いたときにはPDFを選び直してください。ファイルそのものはURLやブラウザストレージに保存しません。

## 4枠のハンコ設定

「02 ハンコを設定」の4つのタブで編集する枠を切り替えます。フォームは1つのままで、名前・ページ・座標・サイズ・単位・不透明度・回転を枠ごとに保持します。「このハンコを捺印する」をオンにした枠を、最大4個まとめて追加します。オフにしても登録内容はURLに保持されます。「この枠を初期値に戻す」は選択中の枠だけに作用します。

初期状態は枠1のみオンです。枠2〜4は名前と位置の例を用意したオフの状態で、必要な枠を編集してオンにしてください。タブは左右矢印・Home・Endキーでも切り替えられます。

枠1のURLは従来と同じ `text`・`page`・`x` などを使います。枠2〜4は `text2`・`page2`・`x2` のように末尾へ枠番号を付けます。使用状態は `enabled`・`enabled2`・`enabled3`・`enabled4` に `1`（使用）または `0`（不使用）を指定します。枠2〜4の設定があり使用状態を省略した場合、その枠はオンになります。従来の1個用URLもそのまま利用できます。

例（2個を同じページに配置）：

```text
?text=高橋&x=20&y=20&text2=田中&x2=45&y2=20&enabled2=1
```

プレビューは選択中の有効な枠のページを表示し、そのページにある全ハンコを描画します。不使用の枠を選択中は、最初の有効な枠のページを表示します。保存は選択タブにかかわらず、有効な全枠・全ページを含みます。全枠オフの場合は保存できません。

## GitHub Pagesへの無料公開（後で行う手順）

1. `npm.cmd run build` を実行します。
2. GitHubに公開リポジトリを作り、生成された **distフォルダの中身** をリポジトリ直下へ配置します。`assets`、`pdfjs`など全てのファイルを含めてください。`node_modules`や個人のPDFは不要です。
3. GitHubの **Settings → Pages → Build and deployment** で **Deploy from a branch** を選び、対象ブランチと **/(root)** を指定します。
4. GitHubが表示する `https://...github.io/.../` を開きます。HTTPSの設定を確認します。

すべてのアセット参照は相対パスに対応しているため、リポジトリ名が付くサブディレクトリでも動作します。JavaScript、PDF.jsのWorker、CMap、標準フォント、WASMを同じサイトに含め、実行時のCDN依存はありません。

GitHub Pages公式手順： https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## 仕様と制限

- 1回の保存につき最大4個のハンコを追加します。同じページにも、異なるページにも配置できます。元のPDFを毎回読み直すため、フォーム変更で以前の印影が残ることはありません。重なる位置を設定した場合は枠1〜4の順で重ねます。
- ダウンロード時のファイル名は元のPDFと同じです。「捺印済み」などの接尾辞は追加しません。同名ファイルが保存先にある場合、ブラウザの設定によって連番が付くことがあります。
- プレビューは捺印済みPDF自体を描画します。元のPDFの本文を画像に変換せず、印影のみを透過PNGとして追加します。
- 印影は端末にインストールされた日本語明朝系フォントを使用します。端末によって字形が変わる場合があります。出力PDFには印影画像を埋め込むため、出力後の字形は固定されます。
- 現行のChrome / Edge / Firefox / Safari向け。古いブラウザは対象外です。
- サンプル版のファイル上限は100MBです。大きなPDFはブラウザのメモリや端末の性能により時間がかかる場合があります。
- パスワード保護PDFは未対応です。保護を解除したファイルを使用してください。
- はみ出すハンコには警告を表示しますが、保存は可能です。ページ外の部分は表示されません。
- 印影の追加機能であり、暗号学的な電子署名・本人確認の機能はありません。電子署名済みPDFの署名維持には対応していません。
- フォーム付きPDFや特殊なPDFの完全な互換性は保証していません。保存前後に確認してください。
- URLには捺印する名前が含まれます。URLを共有すると、その設定も共有されます。

## 検証

```powershell
npm.cmd test
npm.cmd run build
```

自動テストはURLの往復・入力エラー・単位変換・2ページPDF・指定ページだけの捺印・CropBox・0/90/180/270度回転・UserUnit・完全透明を検証します。生成されたPDFをPDF.jsで実際に再描画し、印影の座標と元のテキストが残っていることを確認します。

## 主なファイル

- `index.html`：画面
- `src/main.js`：ファイル選択・プレビュー・URL・保存
- `src/settings.js`：設定検証・座標変換
- `src/pdf.js`：印影生成・PDF編集
- `src/style.css`：画面デザイン
- `dist/`：公開用の生成済み静的ファイル

使用ライブラリ：PDF-LIB（MIT）、PDF.js（Apache-2.0）、Vite（MIT・開発用）。公開用ファイルにライセンス文書を含めています。
